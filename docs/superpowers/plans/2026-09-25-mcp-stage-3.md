# Stage 3 MCP Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** An active Agent execution can call only approved external MCP tools through a short-lived Agent gateway grant, without giving its runtime the external credential.

**Architecture:** Application services own execution/connection policy and temporary credential decryption. An Agent infrastructure adapter holds hashed grants and exposes a narrow HTTP boundary backed by the SDK 0.18.4 stateless MCP server handler. Stage 4 later injects the returned endpoint and grant into Codex; it is not part of this plan.

**Tech Stack:** Java 21, Spring Boot 3.3.4, MCP SDK 0.18.4, Jackson 2, existing Forge Agent hexagonal modules and ForgeIT.

**Spec:** [stage-3-design.md](../../mcp-integrations/stage-3-design.md); [roadmap.md](../../mcp-integrations/roadmap.md) Stage 3.

## Global constraints

- No new microservice, IAM framework, schema migration, OAuth, UI or Codex injection.
- External credentials remain encrypted at rest and are decrypted only around bounded SDK discovery/call; zero plaintext arrays afterward.
- Runtime token is distinct from operator/service credentials; only a hash is retained, and a new invocation receives a new token.
- Every denial precedes upstream I/O. No automatic retry of `tools/call` after an ambiguous failure.
- Keep the accepted Stage 2 DNS-rebinding/TLS gaps marked `NOT_VERIFIED`.

## Review focus

- A disabled and re-enabled connection must not revive a previous token.
- A management Test that leaves a tool unchanged must not silently expand or unnecessarily revoke its grant; changed schema must fail closed.
- A malformed JSON-RPC request or exception containing a synthetic secret must not put that secret in the public response or logs.
- Two invocations or connections with the same tool name must route to their own credential and approved schema.
- Cancel, terminal finish and restart must leave old grants unusable; a timed-out write call must not be replayed.

## Task 1: Grant model and in-memory store

**Files:** New small records/ports under `services/forge-agent/domain/.../mcp` or existing model/port packages; implementation under `infrastructure/local/.../mcp/gateway`; focused unit tests beside it.

**Interfaces:** `issue(trusted execution claim, connection, approved snapshot, deadline) → one-time bearer + grant id`; `resolve(token, connection id) → grant`; `revokeConnection`, `revokeExecution`, `remove`. Store only SHA-256 token hashes and bounded grant metadata.

- [ ] Write failing tests for token uniqueness, hashed storage, wrong connection, expiry, revoke and restart; use a fixed clock and synthetic tokens.
- [ ] Run focused tests and confirm the intended failures.
- [ ] Implement the minimal store with `SecureRandom` and monotonic expiry checks; avoid background refresh or a durable grant table.
- [ ] Re-run tests and commit this self-contained boundary.

## Task 2: Policy owner and management revocation

**Files:** New `application/.../mcp/McpGatewayGrantService` and `McpGatewayRequestService`; existing `McpConnectionService` and `McpProbeService`; focused application tests.

**Interfaces:** Issuer accepts the trusted `AgentSessionExecutionClaim` plus execution deadline and connection ID. It resolves session → node run → workflow run → project from repositories and validates the current lease. Request service resolves the grant and checks live execution, enabled connection, project access, endpoint/auth/credential identity, and exact approved tool fingerprint before returning a list or calling `McpRemoteToolClient`.

- [ ] Write failing tests for foreign invocation/project, expired lease, empty Selected projects, disabled connection, wrong tool/schema, and zero remote calls on denial.
- [ ] Implement issuance and per-request policy without accepting project ID from HTTP/tool arguments. Decrypt the current credential for one SDK call and zero it in `finally`.
- [ ] Add failing tests for Disable → Enable, Remove, endpoint/credential edit, approval reduction and active Test inventory change.
- [ ] Revoke grants from management mutations; retain unchanged tools after an unchanged Test, reject changed schemas. Re-run focused tests and commit.

## Task 3: SDK tool view and safe HTTP endpoint

**Files:** `infrastructure/local/.../mcp/protocol/SdkMcpRemoteClient` (bounded full tool schema discovery stays here), new gateway SDK/HTTP adapter and configuration in the existing Agent modules; local HTTP fixture tests.

**Interfaces:** At issuance, the adapter receives the temporary decrypted credential and exact allowed name/fingerprint set, obtains current SDK `Tool` definitions, and creates a per-grant SDK stateless server view. A narrow Spring servlet adapter validates bearer/Host/Origin/body bounds, uses SDK JSON-RPC deserialization and server handler, and returns only safe errors. Its `tools/call` callback delegates to Task 2's request service; no SDK JSON escapes into domain/Nexus.

- [ ] Write a failing local-HTTP test: a real SDK client initializes, sees only approved tools and calls one; wrong bearer/Origin and guessed tool yield zero upstream calls.
- [ ] Implement only `initialize`, `tools/list`, `tools/call`, bounded JSON POST and safe error mapping. Do not use the stock SDK servlet's raw-exception logging path.
- [ ] Add failing canary tests for malformed requests and unsafe upstream causes in HTTP responses and captured logs; cover two equal tool names in different grants.
- [ ] Re-run focused HTTP tests and commit.
