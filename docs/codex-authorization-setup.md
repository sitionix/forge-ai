# Forge Codex authorization

Forge uses one ChatGPT account per local installation. Open Settings → Integrations and use **Sign in with ChatGPT** on the Codex card. Complete the OpenAI login yourself in the new tab, then wait for the card to confirm the account. If the popup is blocked, use the explicit OpenAI link on the card. Login completion requires a fresh account confirmation; an open login tab or a successful HTTP response alone is insufficient.

The first start requires an explicit Forge login even if a managed profile already contains credentials. Agent stores its approval separately in a control-owned private directory under the routing workspace; provider credentials alone cannot establish that approval. Pending or cancelled login, expired login, and unresolved sign-out remain blocked across Agent restarts. Retry explicit sign-out to confirm cleanup before starting another login. A completed Forge login and its approval survive normal restarts. The approval file contains no account credentials.

The normal runtime lifecycle is `just stop`, `just start`, `just status`. Stop investigating startup at its first failure before attempting login or inference. A normal restart preserves the protected Forge runtime profile. The launcher's `HOME` is the installed runtime home and `CODEX_HOME` is its `.codex` directory. Do not copy terminal credentials or configuration into it. A terminal Codex login, inherited API key, or project provider override cannot authorize Forge. The installed protocol baseline for this change is Codex CLI **0.160.0 and 0.160.1**; unsupported Knowledge generation versions fail closed.

Agent owns authorization and launches Codex through the managed runtime. Knowledge uses Agent's typed local bridge for generation, model discovery, and usage. Its configuration contains only `FORGE_CODEX_AGENT_BASE_URL` (normally `http://127.0.0.1:7091`) and `FORGE_CODEX_SERVICE_TOKEN_FILE` (normally `/etc/forge-ai/codex-service/token`). The service token is distinct from provider credentials, is provisioned as a control-owned mode-0600 file, and is preserved on reinstall. Knowledge retains `NoNewPrivileges=true`. Do not expose either credential in browser requests, logs, or database records.

Use **Sign out** in Settings to invalidate new inference and cancel owned active work. Fresh, tracked, durable, resumed, retried Agent turns and Knowledge generations must then reject with `CODEX_AUTH_REQUIRED`; authorized usage also rejects. Model catalog observation may remain available while signed out. A visible model or runtime `READY` status does not mean inference is authorized. `CODEX_LOGOUT_REQUIRED` or `CODEX_AUTH_CLEANUP_FAILED` means cleanup remains unresolved; retry explicit sign-out after addressing the failure. There is no terminal fallback. If a request fails after a login/cancel/logout attempt, use the explicit status retry before another mutation.

GitHub/MCP authorization is separate. ChatGPT login never selects a project, approves tools, issues an MCP runtime grant, or signs into GitHub. Keep the chosen project and approved tool fingerprints explicit in the MCP connection settings. Signing out of ChatGPT does not delete that independent connection or its OAuth credentials.

## Browser and service interfaces

Console uses the same-origin Nexus prefix `/fgaisox/api/v1/infrastructure/agents/integrations/llm` (with the deployed context path). A provider GET bootstraps the HttpOnly browser-binding cookie. POST login/logout and DELETE cancellation send exactly `{}` as JSON; the browser supplies cookies and Origin normally. Cancellation returns terminal HTTP 200 JSON. Do not put a browser binding in browser JSON, query parameters, or browser storage. After a Nexus restart, reload provider status to renew the in-memory browser binding; an older pending attempt can remain owned by the old binding until expiry.

Agent's `/internal/v1/codex` is a loopback service interface, not a browser route: GET `/models`, GET `/usage`, POST `/generations`, GET/DELETE `/generations/{uuid}`. It requires the separate installation service credential, rejects browser headers, and accepts no arbitrary provider RPC, tools, configuration, repository, or MCP grants. A generation request has exactly `requestId`, `prompt`, `modelId`, nullable `effortId`, `responseMode`, and `timeoutSeconds`; submission returns HTTP 202 and cleanup DELETE returns HTTP 204 after acknowledgment. No Nexus generic proxy exposes this namespace.

## Verification boundaries

`JoinedCodexAuthorizationTest` joins real Agent controllers, filters, lifecycle service, gate, normal inference client, and Knowledge operations adapter around an in-memory protocol peer and a synthetic file-backed account. It proves component wiring and fail-closed behavior, including fixture reconstruction with preserved account data. `NexusLlmAuthorizationIT` runs the real Nexus boot/filter/client against a synthetic loopback Agent HTTP server. These are complementary contract fixtures; they do not prove a real Nexus-to-Agent-to-managed-Codex deployment, actual login, host restart, or operating-system isolation.

Runtime unit tests also execute the launcher's emitted clean-environment command with disposable profiles. The optional installed-CLI characterization can be run with `FORGE_TEST_CODEX_BINARY` set to the native 0.160.0 or 0.160.1 binary; it initializes an empty temporary profile, reads effective config/account, and sends no inference. It does not exercise systemd, privileged installation, or a real account. Do not enable the legacy `forge.codex.live-session-e2e` or `forge.codex.live-recovery-e2e` fixtures as authorization evidence: the boot `LiveCodexRecoveryFixture` currently launches a raw inherited `ProcessBuilder` and does not use the managed isolation boundary.

Actual deployment acceptance still requires the normal host lifecycle, a user-completed browser login, isolated account/read, harmless inference, Knowledge generation/model/usage checks, logout/relogin checks, and independently authorized MCP workflow evidence. Check actual run, turn, tool, and GitHub operation outputs. Synthetic fixtures and natural-language success messages do not replace that evidence.
