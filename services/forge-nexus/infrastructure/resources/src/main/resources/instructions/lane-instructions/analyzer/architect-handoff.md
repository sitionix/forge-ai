# Analyzer Architect Handoff

## Purpose

Prepare implementation-relevant context for `architect`.

## Content

Include only scope-local context needed for architecture and implementation planning:

- scope-owned requirements;
- relevant constraints;
- non-goals;
- risks;
- dependencies;
- possible API needs;
- possible event needs;
- acceptance-oriented notes.

## Shape

Make the handoff:

- compact;
- normalized;
- ordered by implementation relevance;
- explicit about ownership boundary;
- explicit about dependencies;
- clear about expected behavior.

Compress the original task text into architect-ready context.
Preserve possible API and event needs as signals for architect.
Final API and event decisions remain architect-owned.
Final implementation design remains architect-owned.
